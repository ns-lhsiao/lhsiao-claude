# Local devbox-ui Docker Stack

## webui local devbox-ui docker stack

- **The local webui dev environment is a self-contained docker stack started from the `devbox-ui` repo (`/Users/lhsiao/ns/git/devbox-ui`), NOT a connection to a remote tenant DB.** `docker compose up` brings up: a `web` container hosting the PHP BFF (CodeIgniter, php-fpm 8.1) live-mounted from `${NS_WEB_UI_DIR}/src/webui/system_framework → /var/www`, listening TLS on `:443` (host `developer.vbox`/`dev-developer.vbox` → 127.0.0.1); a local `mariadb` (host port 3309, root/1234); an `angular-ui` nginx on `:4200`; plus the `mf-*`/`ms-*` microfrontend/service sidecars. PHP connects to the LOCAL mariadb — the served tenant is whatever that DB holds (this box: `tenant13986db`, config_id=0). Login `developer@netskope.com` at `https://developer.vbox`, webui hash routing `/ns#/...`.
- **The served Angular is NOT `neo/dist`.** `neo/dist` is empty; `angular-ui` mounts it but the app actually loads from `system_framework/UI_Layer/dist/dev-lazy/` (built by `cd neo && npm run build:dev-lazy` → output `../system_framework/UI_Layer/dist/dev-lazy`, deploy-url `/UI_Layer/dist/dev-lazy/`), served by the `web` container off the system_framework mount. `/ns` index.html references `UI_Layer/dist/dev-lazy/main.<hash>.js`. `npm run dev:watch-lazy` (README step 13) is the watch variant; a one-shot `build:dev-lazy` also works.
- **`build:dev-lazy` OOMs V8 with default heap** — a backgrounded `nohup npm run build:dev-lazy` "exit 0"'d but produced NO output dir (silent crash: `FATAL ERROR: Reached heap limit`). Fix: `NODE_OPTIONS="--max-old-space-size=8192" npm run build:dev-lazy`. Build ~110s, main bundle ~14.8 MB.
- **A blank Angular shell (bodyLen 0, login form never renders) is usually a dev-lazy manifest⇄bundle desync, not an app bug.** `UI_Layer/dist/dev-lazy/angular_view.txt` is the bundle-ref manifest PHP serves into `/ns` index.html; an interrupted/OOM'd `build:dev-lazy` leaves it pointing at stale hashes (e.g. `main.aafd1da7...`) that are NOT on disk (disk has `main.443d7a90...`), so every bundle 404s and nothing mounts. Tell: `curl -sk https://<host>/ns | grep dist/dev-lazy` shows a `main.<hash>` that `ls dist/dev-lazy/` doesn't have. Fix: re-run `NODE_OPTIONS="--max-old-space-size=8192" npm run build:dev-lazy` to completion — it rewrites `angular_view.txt` and the bundles together in sync. Confirmed 2026-08-18 (ENG-1129819).
- **To serve a worktree's fix instead of the primary checkout**, repoint `NS_WEB_UI_DIR` and recreate the two file-mount containers: build dev-lazy in the worktree, then `cd devbox-ui && NS_WEB_UI_DIR=<worktree> docker compose up -d web angular-ui`. Both the PHP change (system_framework mount) and the Angular change (dev-lazy under it) swap together. Verify with `docker inspect web --format '{{range .Mounts}}...'` (source path) and `curl -sk https://developer.vbox/ns | grep dist/dev-lazy` (served bundle hash matches the worktree build). Confirmed 2026-08-03 (ENG-1149041).
