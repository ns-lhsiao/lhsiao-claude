# Local devbox-ui Docker Stack

## webui local devbox-ui docker stack

- **The local webui dev environment is a self-contained docker stack started from the `devbox-ui` repo (`/Users/lhsiao/ns/git/devbox-ui`), NOT a connection to a remote tenant DB.** `docker compose up` brings up: a `web` container hosting the PHP BFF (CodeIgniter, php-fpm 8.1) live-mounted from `${NS_WEB_UI_DIR}/src/webui/system_framework → /var/www`, listening TLS on `:443` (host `developer.vbox`/`dev-developer.vbox` → 127.0.0.1); a local `mariadb` (host port 3309, root/1234); an `angular-ui` nginx on `:4200`; plus the `mf-*`/`ms-*` microfrontend/service sidecars. PHP connects to the LOCAL mariadb — the served tenant is whatever that DB holds (this box: `tenant13986db`, config_id=0). Login `developer@netskope.com` at `https://developer.vbox`, webui hash routing `/ns#/...`.
- **The served Angular is NOT `neo/dist`.** `neo/dist` is empty; `angular-ui` mounts it but the app actually loads from `system_framework/UI_Layer/dist/dev-lazy/` (built by `cd neo && npm run build:dev-lazy` → output `../system_framework/UI_Layer/dist/dev-lazy`, deploy-url `/UI_Layer/dist/dev-lazy/`), served by the `web` container off the system_framework mount. `/ns` index.html references `UI_Layer/dist/dev-lazy/main.<hash>.js`. `npm run dev:watch-lazy` (README step 13) is the watch variant; a one-shot `build:dev-lazy` also works.
- **`build:dev-lazy` OOMs V8 with default heap** — a backgrounded `nohup npm run build:dev-lazy` "exit 0"'d but produced NO output dir (silent crash: `FATAL ERROR: Reached heap limit`). Fix: `NODE_OPTIONS="--max-old-space-size=8192" npm run build:dev-lazy`. Build ~110s, main bundle ~14.8 MB.
- **A blank Angular shell (bodyLen 0, login form never renders) is usually a dev-lazy manifest⇄bundle desync, not an app bug.** `UI_Layer/dist/dev-lazy/angular_view.txt` is the bundle-ref manifest PHP serves into `/ns` index.html; an interrupted/OOM'd `build:dev-lazy` leaves it pointing at stale hashes (e.g. `main.aafd1da7...`) that are NOT on disk (disk has `main.443d7a90...`), so every bundle 404s and nothing mounts. Tell: `curl -sk https://<host>/ns | grep dist/dev-lazy` shows a `main.<hash>` that `ls dist/dev-lazy/` doesn't have. Fix: re-run `NODE_OPTIONS="--max-old-space-size=8192" npm run build:dev-lazy` to completion — it rewrites `angular_view.txt` and the bundles together in sync. Confirmed 2026-08-18 (ENG-1129819).
- **To serve a worktree's fix instead of the primary checkout**, repoint `NS_WEB_UI_DIR` and recreate the two file-mount containers: build dev-lazy in the worktree, then `cd devbox-ui && NS_WEB_UI_DIR=<worktree> docker compose up -d web angular-ui`. Both the PHP change (system_framework mount) and the Angular change (dev-lazy under it) swap together. Verify with `docker inspect web --format '{{range .Mounts}}...'` (source path) and `curl -sk https://developer.vbox/ns | grep dist/dev-lazy` (served bundle hash matches the worktree build). Confirmed 2026-08-03 (ENG-1149041).
- **Session backend is `memcached`, NOT the `tenant<id>db.ci_sessions` table** — that table exists but is unused on this stack; `sess_driver` resolves to memcached at runtime despite config.php's DB fallback branch. Cookie value is base64 `nsmemcached` + real id (decode the `bnNtZW1jYWNoZWQ...` prefix to confirm). Session key in memcached = `ci_session:<HTTP_HOST>:<session_id>` (`NS_Session_memcached_driver.php`). Inspect directly: `printf 'get <key>\r\n' | docker exec -i memcached nc -w2 localhost 11211` (raw get shows garbled output if the value is memcached-client-compressed — use PHP's own Memcached ext instead: `docker exec web php -r '$m=new Memcached();$m->addServer("memcached",11211); var_dump($m->get("<key>"));'` for a clean decompressed read). `mariadb` root creds for direct queries: `docker exec mariadb mariadb -uroot -p1234 -e "..."`.
- **Login on this devbox silently orphans the session — `session_regenerate_id()` migrates data to a new memcached key correctly but the response `Set-Cookie` never reflects the new id**, so the browser keeps resending the pre-login cookie forever and `login/isAccessAllowed` always reports `authenticated:false` even though server logs show "successfully logged in." Root: `NS_Session::isRegenerateNeeded()` (`application/libraries/Session/NS_Session.php`) fires `sess_regenerate()` on every `login/authenticate` (session-fixation hardening); on this stack the regenerated id's cookie update is lost (confirmed via raw CDP `Set-Cookie` capture — value never changes across the whole flow, including the authenticate POST response itself). No PHP error/warning surfaces (`error_reporting(E_ERROR|E_RECOVERABLE_ERROR)` globally excludes E_WARNING, and `session_regenerate_id()` failures are warnings). **Workaround (worktree-local only, NEVER commit)**: add an early `return false;` at the top of `isRegenerateNeeded()` with a `DEVBOX-TEMP` comment — disables regen-on-login so writes stay on one stable id (plain writes to a stable id already work fine). Must revert before finishing (`git checkout -- .../NS_Session.php`). Confirmed 2026-08-27/28 (ENG-868849 validation attempt).
- **Fast pre-check for a `$5$` (SHA-256 crypt) password before burning a full Playwright login attempt**: `openssl passwd -5 -salt <salt-from-stored-hash> '<candidate-password>'` and compare byte-for-byte against `admin_users.password`. Extract the salt as the 2nd `$`-delimited field. Saves a ~20min login-flow cycle when the password is simply wrong.
- **Raw `fetch()` to a PHP ajax endpoint (e.g. `/login/isAccessAllowed`) without `X-Requested-With: XMLHttpRequest` returns the SPA's `index.html` shell (200, `text/html`), not JSON** — CodeIgniter's `is_ajax_request()` check fails, routing `NS_Controller`'s non-ajax branches (e.g. `checkForValidSession()`) to a browser `redirect()` instead of an ajax JSON error. Always set that header when probing PHP ajax endpoints directly instead of through the Angular app's own HttpClient.
- **Waiting for `domcontentloaded` before `page.waitForSelector('#username')` on the login page can find ZERO inputs** — `/login` returns a JSON redirect (`{"redirect":"/ns#/login"}`) that the Angular SPA then has to boot and route through; `domcontentloaded` fires before Angular mounts the form. Use `page.goto(url, {waitUntil: 'networkidle'})` for the login page specifically.
- **RBAC v3: `role_id=1` (this devbox's seeded admin) has NO local `role_v3_permissions` rows** — that table only seeds `role_id=3`. Role 1's permissions resolve via an external call (`http://host.docker.internal:3022/roles/1`) which also doesn't grant most Settings pages (e.g. Client Configuration → "permission denied to access the requested page"). Reassigning `admin_users.role_id` to 3 doesn't help — role 3's nav is narrower (no Incidents/API-enabled Protection/Skope IT/App Catalog) and still lacks Client Configuration. This is a seed-data gap, not fixable by role-shuffling; would need either seeding `role_v3_permissions` for the target role or finding/creating an account whose role already has the page.
- **Client-config (and likely other group-bound) saves call out to an external QA/NPE host — `http://um-api-service-ext.qa01-mp-npe.nc1.iad0.nsscloud.net` (User Manager V2 API) — which is unreachable from this devbox** (DNS fails). Blocks ANY group-type client-config save via UI or direct API call, independent of any webui code change. Confirmed 2026-08-28 while validating ENG-868849 PR #18659.
