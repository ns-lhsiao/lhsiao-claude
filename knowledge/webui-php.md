# webui PHP & Testing

## Webui PHP & Testing

- **`webui` worktree has no `vendor/` and no working symlink fix for PHPUnit.** `composer` isn't installed on this machine; `brew install composer` drags in 28 unrelated dependency upgrades — don't. Instead `php -r "copy('https://getcomposer.org/installer','composer-setup.php');"` then `php composer-setup.php --install-dir=/tmp --filename=composer.phar` gets a clean `composer.phar` with zero brew footprint. But primary's `composer.lock` (`src/webui/system_framework/composer.lock`) pins packages needing PHP ≥8.2 (`symfony/filesystem` v7.4.8, `finder`, `process`) alongside one needing ≤7.x (`cache/cache` 2.0.x-dev) — no single PHP satisfies the whole lock file's platform check, and the repo's stated runtime is 8.1 (`php@8.1` via homebrew, at `/opt/homebrew/opt/php@8.1/bin/php` — bare `php` on this machine resolves to 8.5.8, NOT 8.1, despite `which php`/`php -v` in a plain shell showing 8.1.32 elsewhere in the session; the two didn't agree, don't trust one check). Separately, symlinking primary's already-installed `vendor/` into the worktree (the usual node_modules-style fix) causes `PHP Fatal error: Cannot redeclare rangeMatch()` — the same helper file loads once via the worktree's own `application/helpers/` and once through a path that resolves back through the symlink into primary, so CodeIgniter's helper loader double-includes it. Copying files into primary and running there (the documented fallback for webui PHP tests) is unsafe when primary's checked-out commit predates the worktree's base by any meaningful margin — silently reverts adjacent files. `git worktree add --detach` at the branch tip + vendor symlink fails identically (`Cannot redeclare rangeMatch()`) — vendor's autoloader resolves helper paths through primary's filesystem root, double-loading `application/helpers/`; no worktree variant works. Net effect: as of 2026-07, there is no clean way to execute PHPUnit for a `develop`-based webui worktree on this machine; fall back to `php -l` + static review and say so explicitly rather than claiming tests ran.
- **UPDATE 2026-08 — a REAL vendor COPY (not symlink) DOES run PHPUnit in a webui worktree.** The symlink fails because PHP resolves `__DIR__` inside `vendor/composer/*.php` through the symlink to primary's realpath, so composer's `$baseDir` points at the PRIMARY checkout — the autoloader then loads model/helper source from primary while `tests/bootstrap.php` loads from the worktree, double-including `application/helpers/NS_string_helper.php` → `Cannot redeclare rangeMatch()`. Fix: `rm vendor && cp -R <primary>/src/webui/system_framework/vendor ./vendor` (a real dir, ~138M). Now `__DIR__` resolves to the worktree, `$baseDir` = worktree, autoloader + bootstrap agree, no redeclare. Composer autoload arrays are runtime-relative (`$baseDir . '/...'`), so a plain copy recomputes paths correctly — no `composer install` needed. Run from the tests dir: `cd src/webui/system_framework/tests && ../vendor/bin/phpunit -c phpunit.xml --filter <Class> models_no_db/<File>.php`. Confirmed on a PR-based worktree (ENG-868849, branch off `pr/ENG-868841/...`): 94 tests ran, only pre-existing failures. Note: `testValidateDataBothFlagsOffUsesLegacyPath` in `Client_configuration_modelTest.php` fails standalone (`self::$globalCI->session` null at its first `set_userdata` line) — a pre-existing test-isolation flaw, reproduces on base with changes stashed; not a regression. PHP on this machine is now 8.5.8 (deprecation notices for `E_STRICT` and optional-param-before-required are pre-existing noise, not errors). **Don't write NEW tests using the same `self::$globalCI->session->set_userdata(...)` pattern** to force a feature-flag-per-provisioner helper (e.g. `useUserManagerApi()`) — confirmed 2026-08-28 that a brand-new test using this exact pattern failed the same way, even running the whole file (not just standalone/`--filter`). If a helper reads `get_instance()->session` with no `$GLOBALS['unit_test_...']` override available, prefer picking a test scenario where the ambient/default flag state already gives you the branch you need, rather than forcing it via `self::$globalCI->session`.
- **`tsc -p tsconfig.json --noEmit` in `src/webui/neo` has a ~490-error pre-existing baseline.** Do NOT treat a nonzero count as evidence your change broke typing, and do not report the raw number as a PR finding. Composition: 146 TS2307 for modules that aren't installed (`@storybook/*`, `storybook-addon-designs`, `@components/profile-card/*`), 76 TS2341, 72 TS2554, 53 TS2339, plus `typings.d.ts` TS2451 `Cannot redeclare 'module'/'global'` colliding with `@types/node/globals.d.ts`. Cause: the root `tsconfig.json` includes `*.stories.ts` and `*.spec.ts` that the Angular build config excludes, so nothing in CI ever typechecks them. Correct verification: `git stash push -- src/webui`, re-run, then `diff <(grep "error TS" before | sort) <(grep "error TS" after | sort)`. Expect the only delta to be line-number shifts on identical errors in spec files you edited. Confirmed 2026-07 (ENG-1055073): 490 before, 490 after, delta = 3 shifted lines.
- **Use `$this->callService()` for testability**, not the global `callService()`. `NS_Model::callService()` delegates via `call_user_func_array` and is mockable via `getMockForModel('...', ['callService'])`.
- **Tenant migrations don't ship with PHPUnit tests**. Files under `system_framework/application/migrations_ui/tenant/` have no companion tests by convention. Validation is operational; record the matrix in QA Test Recommendations on the ticket.
- **`showErrorToast` first arg must not be `null`** — accesses `error.message` without a guard. Pass `{}` when there's no real error.
- **`DevicesFilters.test.tsx` mocks the entire `devices.helper` module** — adding a new export will fail at test time. Compose new logic into an already-mocked function instead of adding a new import.
- **mf-client uses Jest via craco**, not vitest. `npx vitest` can't resolve `~/` aliases. Run `npm test -- --testPathPattern='<pattern>'`.
- **mf-client `test:coverage` needs `--max-old-space-size=8192` and `--forceExit`**. Default 4 GB OOMs at ~2450 tests with `--runInBand`. Jest hangs after passing due to leaked async handles (valtio devtools, MSW).
- **Always lint changed files before committing** — Prettier multi-line formatting errors aren't caught by Jest. Run `npx eslint <files>` especially when bypassing pre-commit.
- **SonarQube new-code coverage = diff lines only**, not whole-file %. Verify locally with `--coverageReporters=json` against `git diff` line numbers.

## PHPUnit Mocking

- **`getMockForModel` throws `MethodCannotBeConfiguredException` on `private` methods.** PHPUnit mock builder can only configure `public` or `protected` methods. Any method you want to stub/mock in a test MUST be `protected` (or `public`). When adding a new helper method that tests need to mock, declare it `protected`, not `private`. Pattern: `retainOldGroupScimId` (ENG-868833) was `private` → CI threw `MethodCannotBeConfiguredException` on every test using `resetSaveClientConfigMock` → fix: change to `protected`.
- **`getMockForModel($class, [$methods])` (PHPUnit legacy `setMethods()`) only stubs the LISTED methods — every unlisted method keeps its REAL implementation and runs for real, including real HTTP calls.** When a code change makes an already-tested method (e.g. `getOUClientList()`) call a NEW dependency method (e.g. a new `doGroupsExistByScimIds()`), every EXISTING test that exercises that code path with a mocked `user_manager_v2_model` must add the new method to that mock's method list too, or the real (unmocked) implementation fires — a real UM API call inside a unit test. Symptom would be a network-call error or hang, not an assertion failure. Fix: before shipping a new internal call inside an already-covered function, grep the test file for every `getMockForModel(..., [...])` call touching that dependency and extend the method list; then run the FULL test file (not just new tests) to catch it — running only the new tests in isolation won't surface this regression. Confirmed 2026-08-28 (ENG-868849): adding a `doGroupsExistByScimIds()` call inside `getOUClientList()`'s rename-gate branch broke two pre-existing tests (`testGetOUClientListWithRenameGateOnly`, `testGetOUClientListWithRenameOnlyFetchesUGNotSAML`) until their `user_manager_v2_model` mocks were extended.

## Webui Steering Exceptions / bypass_settings_v2

- **`bypass_settings_v2.dynamic_steering_mode` defaults to `-1` (NOT NULL).** Any INSERT that omits the column lands as `-1`. UI list query for dynamic-steering configs filters `WHERE dynamic_steering_mode IN (0,1)` (`Steering_exception_model::getSSLAppsConfigNew`), so `-1` rows are invisible to the admin. Schema source: `migrations/166_location_based_steering.php:39`. Bug source: `Steering_exception_model::addNewFromAppInfoToTenantDb` INSERT lacks the column (file:line ~2105). Repro: ENG-1031514.
- **Webui list query and pycore/nsbypass.json consumer disagree on `ds_mode=-1`.** UI hides the row; pycore treats unknown ds_mode as off-prem and still emits it in `nsbypass.json`, so the client receives the bypass while the admin can't see/manage it. When investigating "customer says it's there but UI doesn't show it" for steering exceptions, suspect ds_mode mismatch first. Repro: ENG-1031514 — Fujifilm tenant 15724, 51 ssl_pinned_app rows in nsbypass.json absent from UI.

## Webui RIS references / dns_profile

- **`if ($obj)` is NOT an emptiness guard after `json_decode($json)` without the assoc flag.** An empty stdClass is truthy in PHP (verified 8.5.8): `json_decode('{"dns_profile":{}}')->dns_profile` → truthy stdClass, `is_array()` false, `(string)$o->id` → warning + `""`. So `dns_profile: {}` in `inline_policies.rule_data` yields a bogus one-element RIS reference id `[""]` that passes `_count($ids) > 0` and gets shipped to RIS forever. `Inline_policies_ris_model::getIdsByRisKey` DNS case (`application/models/Inline_policies_ris_model.php:81-90`) has this bug; PR #18694's `id_uuid`-preference fix does NOT fix it. Guard with `is_array()`/`(array)` emptiness, not object truthiness. Repro: ENG-1221764 tenant 27606 rule 26.
- **`rule_data` is object-decoded, not array-decoded**: `Inline_policies_ris_model::getAppliedPolicy` → `json_decode($row->rule_data)` (no `true`); `Inline_policies_model.php` uses `json_decode($policy->rule_data, false)`. The `is_array()` branch in `getIdsByRisKey` is therefore dead for the read path but live for the write path (`$this->input->post('dns_profile')` yields arrays).
- **`rule_data.dns_profile.id_uuid` is NOT written by webui.** `git grep id_uuid origin/develop` returns zero product hits — the field originates outside webui (cfw dataplane / cfw-api-service; `service` repo has it in `cfw/dataplane/.../dns_profiles/*.json`). Any webui fix that keys off `id_uuid` depends on an external producer and will be absent on tenants that never got the shim. Also `dns-profile-criteria-picker.component.ts` `dnsProfilePickerOnChange` emits only `{id, name}`, so a UI re-pick drops `id_uuid`.
- **`Inline_policies.php:1976-1985` stores the posted `dns_profile` verbatim** (no DB existence check) and, when `!isDnsProfilesApiV2Enabled()`, does `$dnsProfile['id'] = intval($dnsProfile['id'])` — a uuid `id` silently becomes `0` if the flag is ever off during save. Latent corruption vector for uuid→numeric-id regressions.
- **v1 `dns_profiles` and `dns_profiles_v2` have independent AUTO_INCREMENT sequences.** `migrations_ui/tenant/343_create_dns_profiles_v2_table.php` creates an empty table populated by cfw-api-service; there is NO webui migration copying v1→v2 or backfilling `inline_policies`. Never map a legacy numeric `dns_profile.id` to v2 by numeric id — it resolves to an unrelated profile. Repro: ENG-1221764 tenant 25559 (v1 id 3 = "Sinkhole DNS Security Risks", v2 id 3 = "Default DNS Profile").
- **RIS `missing_objects.ris` is echoed verbatim from RIS**, not computed in webui (`Ris_v2_model::integrityCheck`, `checkObjectExistence`). The "missing token" in a report is exactly the string webui sent in `objects.<key>.ids`. Per-object checks are gated by `getObjectMigrationFlagName` — dns requires `dns_profiles_api_v2_enabled`, so a long-standing defect only surfaces when that flag is turned on for a tenant (making Jira affectsVersion pure observation-time).
