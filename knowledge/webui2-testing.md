# webui2 Browser Validation

## webui2 hybrid Playwright: validate a data-driven UI render when the tenant lacks the data

- **A frontend-only render bug (label/format derived from response data) can be browser-validated even when the tenant can't hold the triggering data — mock the API response with `playwright-cli route`.** ENG-1154087: Client Config list header derived from `configs[0].targets[0].type`; the QA tenant (13986) had ZERO OUs synced (`GET /api/v2/users/attributes/ou` → `totalCount 0`) and the backend rejects a create with a fabricated OU (`{"error":{"message":"invalid OU"}}` — OU values are validated against the directory sync). So no real `organizational_unit` config could exist. Fix: `playwright-cli -s=<sess> route "**/api/v2/clientconfiguration/client/config?*" --status 200 --content-type application/json --body "$BODY"` where `$BODY` is the REAL response with `data[first-non-default].targets[0].type` rewritten to `organizational_unit`. Confirmed header rendered "Organization Unit" on the real React hybrid page (verified via `client-configuration-*` testids + HYBRID PROXY badge, NOT legacy Angular). Key subtlety: the list endpoint returns BOTH the paged non-default configs AND (on the last page) the pinned default row; the page computes `configs` by fetching non-default at `offset+1` and appending default at the end, so `configs[0]` = first non-default. The mock body MUST exclude the default config (priority -1) or `configs[0]` resolves to `type:'default'` and the derived label falls through to the default branch — masking the fix. Also: after `route` + `reload`, the hybrid drops React mount; re-clear `sessionStorage.balkan_pages` and hash-nav to `#/settings?view=clientConfiguration` to remount. Confirmed 2026-08-06.
- **webui2 worktree Vite must serve the WORKTREE, not the primary checkout.** Primary's `pnpm dev` occupies :3000 serving base code. Kill it (`lsof -ti:3000 | xargs kill`), copy `.env.local` into the worktree's `apps/shell/`, start `pnpm --filter shell dev --port 3000` from the worktree. Verify with `lsof -p <pid> -a -d cwd` (cwd must be the worktree's `apps/shell`) before trusting a browser result. Confirmed 2026-08-06 (ENG-1154087).

## webui2 Balkan-migrated page browser validation (RBAC/flag gate)

- **A webui2 React page that is RBAC- or per-tenant-flag-gated is NOT reachable via the pure-React dev server (`pnpm dev`, `:3000`) against a tenant that lacks the grant — the route's `beforeLoad` `resolveApiGroupPermission(...).canRead()` returns false and TanStack Router `throw redirect({to:'/dashboard'})` bounces you to the dashboard.** The path route `/ns/settings/<page>` silently becomes `/ns/settings/<page>#/dashboard` (empty body, "Welcome to Netskope Admin Console"). The HASH route `/ns#/settings/<page>` instead serves the LEGACY Angular renderer (h1 present but zero `<feature>-*` React testids) — screenshotting it validates nothing. Confirmed 2026-08-05 (ENG-1153691, client-configuration gated on `ApiGroup.CLIENT_CONFIGURATION` RBAC + per-tenant `balkan_phase2_client_configuration_enabled`).
- **Correct fix: use the `/wb:setup:angular-shell` hybrid dev stack instead.** It runs webui2 React mounted INSIDE the Angular shell via the `angularHybridPlugin` Vite middleware, which forces `ng_balkan_migration_enabled=true` and uses `public/signed_off_pages.json` redirect entries (`{webui2_route, flag_checker, stage}`) to swap the migrated page to React. Stack: local ms-webui (`:8080`), Angular `dev:watch-lazy` dist (`UI_Layer/dist/dev-lazy/`, must have `angular_view.txt`), and Vite (`:3000` default). `.env.local` needs `PUBLIC_LOCAL_API_PATHS=/api/v2/balkan,/api/v2/rbac`, `PUBLIC_PATH_PREFIX=/mf/shell`, `ANGULAR_DIST_DIR=<webui>/.../dist/dev-lazy`. Config sources: `~/.claude/tenants.json` (proxy URL), `~/.claude/db.json` (`mariadb.tenantid`). This renders the REAL React page (verify via `<feature>-*` testids + `balkan-shell-host`), bypassing the pure-React route redirect.
- **Login through the hybrid must land the cookie on `localhost`, not the QA domain.** `goto localhost:<port>/ns/#/login` redirects to `https://<tenant>/auth/login` (QA domain) — logging in there sets the cookie for the QA host and localhost still shows the login form. The localhost login `<form action>` posts to `localhost:<port>/auth/login` (proxied): fill+submit THAT form so the session cookie is scoped to localhost. After login, clear `sessionStorage.balkan_pages` (30-min TTL cache) before hash-navigating to the migrated page. Confirmed 2026-08-05.

## Fastest path for a data-independent render/placement fix: pure-React `pnpm dev` + MSW mock groups (no tenant, no hybrid shell)

- **When the fix is a pure frontend render/placement change (no live-data or per-tenant-config dependency), skip the hybrid Angular stack and tenant entirely — run the worktree's `pnpm dev` with `VITE_MOCK_GROUPS` and MSW authenticates + serves the page.** webui2 MSW handlers are grouped opt-in (`src/mocks/browser.ts` `MockConfigKey`), seeded from `VITE_MOCK_GROUPS=GROUP,GROUP` (also togglable at runtime via `window.__shell_mock_config__.enable('mock_<x>')`). Without any groups, `pnpm dev` proxies to the real QA backend and the pinger 401s → full-page redirect to `/auth/login/local`. Set `VITE_MOCK_GROUPS=PINGER,RBAC,<FEATURE>` (e.g. `CLIENT_CONFIGURATION`) so the pinger + `getRoleFunctionPrivileges` RBAC + feature endpoints are mocked; the route's `beforeLoad` `canRead()` then passes and the REAL React page mounts. Verify via `<feature>-*` testids. This qualifies the "NOT reachable via pure-React dev server" note above: that was about a real tenant lacking the grant — MSW sidesteps the grant. `VITE_MSW_ENABLED` defaults on in dev (opt-out with `=false`); `CORE` group (platform flags, etc.) is always on. Confirmed 2026-08-25 (ENG-1209514, client-configuration).
- **Force feature flags in dev via `VITE_FLAG_OVERRIDES=<raw_flag>:true,<raw_flag2>:true`** (comma-separated `key:value`; shim in `src/shared/feature-flags/useFlag.ts`, `VITE_FORCE_FLAGS=true` forces ALL on). Use the RAW PHP/LD flag name, not the webui2 camelCase alias — e.g. `nplan6711_auto_reenable_ns_client_after_disablement:true`. Env vars pass inline to `pnpm dev`; no `.env.local` edit needed.
- **Worktree `pnpm dev` auto-hops ports when :3000-:3003 are occupied by other feature stacks** — it prints `Local: http://localhost:<port>/ns/`. Grep the startup log for the actual port; do NOT assume :3000. This is a monorepo `turbo`/Vite `pnpm dev` (serves the worktree it's launched from), distinct from the older `pnpm --filter shell dev --port 3000` note above.
- **ntskui `CheckboxField` cell click:** the clickable target is the `button[role=checkbox]` inside `[data-testid=client-config-field-<name>]` (see line 19). In playwright-cli `eval`, `cell.querySelector('input,[role=checkbox],button').click()` toggles it; read DOM order with `a.compareDocumentPosition(b) & Node.DOCUMENT_POSITION_FOLLOWING`.

## NPLAN-669 hybrid validation gotchas (2026-08-20, playwright script mode)

- **QA tenant rejects headless Chrome UA** ("Safari 0 is not supported") — login fields never render, blank page. Fix: keep `headless: true` (skill mandate) but launch with `channel: 'chrome'` AND override context `userAgent` to a real desktop Chrome string (`Mozilla/5.0 (Macintosh...) ... Chrome/131.0.0.0 Safari/537.36`). Login redirects to QA domain → copy cookies to `localhost` (filter out `__Host-`/`__Secure-` prefixed, set `secure:false sameSite:Lax`) so Vite proxy forwards authed requests.
- **client-config API is NOT an ms-webui domain.** `/api/v2/balkan` client-config calls go API Gateway → `client-oppy-configuration` service directly, so routing them to local ms-webui 404s ("Neither React nor Angular detected"). In `.env.local` REMOVE `PUBLIC_LOCAL_API_URL` and `PUBLIC_LOCAL_API_PATHS` so ALL API routes to the QA gateway. (Contrast: RBAC/balkan pages that ms-webui DOES serve want the local paths — depends on which service owns the endpoint.)
- **Hash-nav must wait for Angular hydration.** Firing `window.location.hash='#/settings?view=clientConfiguration'` before Angular hydrates real nav links drops back to the bootstrap script. Wait for `document.querySelectorAll('a[href*="settings"], nav a').length > 3`, then clear `sessionStorage.balkan_pages`, set hash, then poll up to 45s for React table `[data-testid^="client-configuration-name-"]` with loading spinner cleared.
- **ntskui `Checkbox` = `button[role="checkbox"]`, NOT `<input>`.** No `name` attr (all inputs `name=""`). Select by `[data-testid="client-config-field-<name>"]`; read STATE via `aria-checked`/`aria-disabled` attributes — Playwright `.isChecked()`/`.isDisabled()` and the `disabled` prop do NOT apply. `CheckboxField` also sets `id="client-config-<name>"`. Working script: `/tmp/pw-runner/validate-nplan669-hybrid.js` (8/8 pass against QA tenant 13986).
