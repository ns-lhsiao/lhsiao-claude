# Worktrees, node_modules, Lockfiles

## Worktrees, node_modules, Lockfiles

- **Line numbers from the primary checkout do NOT transfer to a fresh worktree.** A worktree created from a just-fetched `origin/<base>` sits on a newer commit than the primary checkout, so grep hits recorded during exploration drift. Symptom: `Read(file, offset=8390)` lands hundreds of lines away from the target (`other_config.py` flag was at 8396 in primary, 9051 in worktree; `setting_list.py` 1206 → 1245). Fix: after `git worktree add`, re-grep every target symbol INSIDE the worktree before any Read-by-offset or Edit. Never carry offsets across checkouts. Also means OpenSpec `tasks.md` line refs authored from primary greps are advisory only. Confirmed 2026-07 (ENG-1055073, service repo).
- **mf-client worktree**: symlink `node_modules` from primary (`ln -s ../mf-client/node_modules node_modules`). `npm install`/`npm ci` mutates `package-lock.json` and wastes minutes. Tests, eslint, prettier, craco all resolve through the symlink.
- **pnpm worktree**: symlink BOTH the root `node_modules` (hosts `lint-staged`) and each `apps/<app>/node_modules` (hosts `vitest`) to the primary checkout. Failure: `Command "lint-staged" not found` on commit, or `vitest: command not found`. If `pnpm install` ran in the worktree, `rm -rf` the real `node_modules` before re-linking.
- **webui2 worktree, also symlink every `packages/*/node_modules`**, not just root + `apps/shell`. Missing `packages/api/node_modules` breaks `pnpm --filter shell test` with `Failed to resolve import "msw/node" from ".../packages/api/src/msw.node.ts"` — the vite test transform resolves `packages/api`'s own deps from its own `node_modules`, not the root one. `ls packages/*/node_modules -d` in the primary checkout to find which packages need it (confirmed: `api`, `shared-types`, `migrations-review`).
- **pnpm add in a worktree** fails with `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE` — the worktree's `node_modules` is a symlink to the primary's `.pnpm` store. Run `pnpm --filter <pkg> add <dep>` in the **primary** checkout instead. Edit `package.json` in the worktree first if you want it committed alongside the feature.
- **mf-client worktree husky**: `.husky/_/husky.sh` is created by `prepare` during `npm install` and not tracked. Before first commit: `mkdir -p .husky/_ && cp ../mf-client/.husky/_/husky.sh .husky/_/husky.sh`. Don't bypass with `core.hooksPath=/dev/null` — lint-staged runs prettier fixes during commit.
- **webui worktree**: For Angular tests, `cd src/webui/neo && npm ci`, then `./node_modules/.bin/jest --testPathPattern=...`. Don't use `npx jest` (pulls jest 30 which renamed to `--testPathPatterns`; project pins jest 29). Same trap for lint: `npx eslint <file>` pulls unpinned eslint 10.9.1 (flat-config only, no `eslint.config.*` in this repo → hard error) and separately gets mangled by the RTK shell hook ("JSON parse failed: EOF"). Fix: after `npm ci`, use `./node_modules/.bin/eslint <file>` directly.
- **OpenSpec artifacts created in primary checkout before the worktree exists don't transfer.** `openspec new change`/`opsx:ff` run in the primary checkout write untracked files under `openspec/changes/<name>/` — `git worktree add` only carries committed history, so the worktree starts without them. Fix: after creating the worktree, `mkdir -p <worktree>/openspec/changes && cp -r <primary>/openspec/changes/<name> <worktree>/openspec/changes/`, then `rm -rf` the primary's untracked copy once confirmed copied (avoid a stray duplicate lingering in primary). Confirmed 2026-08-28 (ENG-1172829, webui).
- **webui PHP tests procedure** (fallback when copy-into-primary is safe): symlinking `vendor/` from primary causes `Cannot redeclare` errors, so copy changed files INTO primary, run `cd tests && php ../vendor/bin/phpunit --configuration phpunit.xml --filter='...'`, restore. The `--configuration` flag is required for `APPPATH` bootstrap. **WARNING**: only safe when primary is on the same base commit as worktree — otherwise the file copy silently reverts adjacent code (e.g. tests added by a recent PR). Failure signature: `git diff origin/develop` shows tests being deleted that you never touched. See the Webui PHP § entry for the full "no clean way" caveat.
- **`npm install` in worktrees** produces large `package-lock.json` diffs from dependency re-resolution. Always `git checkout -- package-lock.json` before committing.
- **webui2 worktree recovery when primary checkout deleted**: dangling `node_modules` symlinks (worktree → `/Users/lhsiao/ns/git/balken/webui2/...`) break Vite with `vite: command not found`. Fix: `rm node_modules apps/shell/node_modules` → `pnpm install` in worktree (becomes self-contained) → `pnpm --filter @ns/api build` (required after fresh install or `apps/shell` errors with `@ns/api/* could not be resolved`). pnpm's post-install script also rewrites `apps/shell/.env.local` to the default React-only template — re-write hybrid config (`PUBLIC_LOCAL_API_PATHS=/api/v2/balkan,/api/v2/rbac`, `PUBLIC_PATH_PREFIX=/mf/shell`, `ANGULAR_DIST_DIR=...`) before restarting Vite.
- **webui2 worktree `pnpm run check` / `tsgo --noEmit` reports dozens of errors outside your feature** (`@ns/api/certificates` unresolved, `@ntskui/react` prop mismatches, TS2589 deep instantiation) when `node_modules` is symlinked from a primary whose deps or `packages/api` build are stale. Not your regression: filter with `pnpm exec tsgo --project tsconfig.app.json --noEmit 2>&1 | rg '<feature-dir>'` and run `oxlint`/`oxfmt --check` scoped to the feature dir; state the filter in the PR. 2026-09-03 (ENG-1252057).
